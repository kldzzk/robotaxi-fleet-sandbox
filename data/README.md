# 城市预设数据

`cities.json` 存放模型输入。当前包含 1 个论文复现基准 + 5 个由地方月报聚合的真实城市。
所有数字都是**聚合指标**，不是原始明细。

## 字段

| 字段 | 必填 | 含义 |
|---|---|---|
| `key` | 是 | 唯一标识，命令行用 `--city key` 指定 |
| `name` | 是 | 展示名称 |
| `population` | 否 | 城市人口 |
| `base_daily_orders` | 是 | 日均出行订单 |
| `traditional_fleet` | 是 | 传统车队规模（隐含活跃运力） |
| `traditional_daily_orders_per_vehicle` | 是 | 传统车单车日均订单 |
| `robotaxi_daily_orders_per_vehicle` | 是 | Robotaxi 单车日均订单（默认与传统车相同） |
| `substitution_ratio` | 否 | 论文校准的订单替代比例，默认 0.27 |
| `fleet_basis` | 否 | 车队口径：`active` / `implied_active` |
| `as_of` | 否 | 数据截至月份 |
| `window` | 否 | 聚合窗口，如「最近6个月中位数」 |
| `derived_orders` | 否 | 订单是否由「单车订单 × 活跃车辆」派生 |
| `source_url` | 否 | 可公开来源链接（没有则省略） |
| `note` | 否 | 数据说明 |
| `scoring` | 否 | 六个维度的 0–100 评分 |

## 重新生成

原始数据不随仓库分发。若你本地有采集目录，可重新聚合：

```bash
python scripts/build_cities.py --source "D:/萝卜快跑/data"
```

脚本会覆盖 `data/cities.json`，并打印每个城市的聚合结果。

## 新增一个城市

1. 在 `cities.json` 的 `cities` 数组里复制一条；
2. 改 `key` / `name` 与各项参数；
3. 运行 `python -m robotaxi_fleet analyze --city 你的key` 检查。

建议保持 `traditional_fleet = base_daily_orders ÷ traditional_daily_orders_per_vehicle`，
否则「传统车队降幅」会与情景压力不完全相等（模型仍会正确计算，但口径需说明）。

## 数据政策

- **不要**提交 CEIC / EPS 等付费数据库的原始数据。
- **不要**提交政府依申请公开的原始明细。
- 仓库只放聚合后的派生指标；有公开 URL 的注明来源，没有的省略。
- 正式引用前请核对口径与时间窗口。

## 关于 `paper_baseline`

用于复现论文口径：

- 日均订单 942,000，传统车队 47,100（= 942,000 ÷ 20）；
- 5%/10%/20% 订单压力 → 2,355/4,710/9,420 辆 Robotaxi。

参数为拟合基准，**不是**某个城市的官方数据。
